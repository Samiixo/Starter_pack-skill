# Starter Pack v2.0: ритм проекта

Комплект из четырёх файлов, который задаёт агенту порядок работы с
документацией: где что лежит, что опасно менять, на чём остановилась прошлая
сессия и какие правила в этом проекте.

Версия 2.0 отличается от исходного комплекта одним: **правила стали
проверяемыми**. Исходник весь держался на прозе, и первое же правило он нарушал
сам - ссылался на `README.md`, которого в комплекте не было.

## Когда применять

- Проект стартует: нужен порядок в документации с первого дня.
- Агент читает файлы наугад и сжигает контекст без пользы.
- Прошлая сессия закончилась, и непонятно, что сделано и что открыто.
- Документация разошлась с кодом и начала врать.
- Новый агент тащит обратно план, который человек уже отверг.
- Нужно проверить, не указывает ли документация на несуществующие пути.

## Четыре файла и их роли

| Файл | Отвечает на вопрос | Кто пишет и когда |
|---|---|---|
| `AGENTS.md` | какие в проекте правила и ритм | человек задаёт; агент дописывает новые правила |
| `INDEX.md` | где что лежит (вопрос -> файл) | агент: создал/удалил/переименовал файл |
| `MAP.md` | что опасно, что чужое, чему нельзя верить | агент: появилась горячая или запретная зона |
| `docs/STATE-LOG.md` | на чём остановилась прошлая сессия | агент: в конце каждой нетривиальной работы |

Разделение ролей - главное, что в исходном комплекте размывалось:

- **README** отвечает «что это и как запустить», и только в нём живёт дерево
  проекта.
- **INDEX** отвечает «где это лежит», без дерева и без истории.
- **MAP** отвечает «чем за это платить», то есть семантика, невидимая из `ls`.
- **STATE-LOG** отвечает «что уже сделано», и читается с конца.

Один факт живёт в одном файле и ссылается из остальных. Два места, где описано
одно и то же по-разному, разъезжаются за месяц.

## Правило, которое нарушал сам исходник

> Каждая ссылка в документе должна вести в реальное место.
> Документ с выдуманными путями хуже отсутствия.

Исходный комплект ссылался на `README.md`, которого в нём не было. Поэтому
правило теперь проверяется:

    python tools/doc_lint.py <каталог-проекта>

Проверяет: все четыре файла на месте, все ссылки ведут в существующие файлы,
не осталось плейсхолдеров, нет опечаток в инструкциях, дерево проекта не
размножено по двум файлам, журнал не переписан вместо дополнения, раздел
«Заморожено» на месте, и нет символов, которых нет в cp1251.

## Создание комплекта

    python tools/init_docs.py --target <каталог-проекта> --dry-run
    python tools/init_docs.py --target <каталог-проекта> --project-name "Название"

`--dry-run` показывает, что будет создано, и ничего не пишет. Существующие
файлы не затираются: инструкция комплекта прямо запрещает затирать
существующий `AGENTS.md` вслепую, поэтому `init_docs.py` либо отказывается от
файла, либо с `--force` делает `.bak`.

Комплект указывает на `README.md`, поэтому при создании в проекте без README
инструмент предупреждает об этом прямо, а `--create-readme-stub` создаёт
заготовку. Иначе создание комплекта сразу порождало бы битую ссылку - ровно
тот дефект, из-за которого сделана версия 2.0.

Сразу после создания `doc_lint` по комплекту даёт FAIL `placeholders_left`:
шаблоны заполняет агент, по фактам репозитория. Это проверка работает, а не
поломка. Зелёным комплект становится после заполнения.

## Ведение журнала

    python tools/state_log.py --target . --wave "правка авторизации" \
        --done "что сделано, с фактами" --open "что осталось и что знать дальше"

Дописывает запись в конец `docs/STATE-LOG.md`, никогда не переписывая прошлые.
Хеш берётся из `git rev-parse`, и если это не git-репозиторий, пишется `none` -
выдуманный хеш хуже отсутствующего.

## Ритм сессии

1. **Заходишь**: хвост `docs/STATE-LOG.md` и `git status` / `git log -3`.
2. **Разведываешь**: `INDEX.md` (где что) -> нужный раздел README -> код.
   Не читать файлы «на всякий случай».
3. **Меняешь**: точечно, в рамках задачи. Архитектурные решения - сначала
   человеку.
4. **Проверяешь**: минимум сборка и тесты; для UI и рантайма - живой запуск,
   если это возможно без риска.
5. **Финализируешь**: запись в STATE-LOG, обновление INDEX при изменении
   состава файлов, MAP при появлении новой опасной зоны, README при изменении
   архитектуры.

Подробно каждый шаг - в `references/rhythm.md`.

## Раздел «Заморожено»

В `AGENTS.md` есть таблица планов, которые человек отверг или отложил. Она
существует ровно для одного: чтобы новый агент не притащил их обратно. Это
самая частая форма бесполезной работы - не ошибка, а повторное предложение уже
отклонённого. Замороженное возвращается только по прямому запросу человека.

## Что этот комплект намеренно не делает

- Не хранит код в документах, только ссылки на файлы.
- Не дублирует дерево проекта: оно живёт в одном месте, в README.
- Не ведёт историю в STATE-LOG как журнал изменений: там финалы сессий, а
  история - в `git log`.
- Не заводит слоты INDEX «на будущее»: пустой слот удаляется.

## Структура

    SKILL.md                        этот файл
    templates/                      четыре файла комплекта, готовые к копированию
      AGENTS.md  INDEX.md  MAP.md  STATE-LOG.md
    references/
      files-guide.md                за что отвечает каждый из четырёх файлов
      rhythm.md                     ритм сессии по шагам
      traps.md                      ловушки, ради которых комплект существует
    tools/
      init_docs.py                  создание комплекта в проекте
      doc_lint.py                   проверка, что документация не врёт о репозитории
      state_log.py                  запись финала сессии в журнал
    examples/                       пример заполненного комплекта
    tests/run_selftest.py
    docs/original/                  исходный комплект, как есть, для истории
