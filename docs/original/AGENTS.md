## Порядок работы
1. **Заходишь** → STATE-LOG хвост (см. раздел «Поддержание порядка») + `git status`/`git log -3`.
2. **Разведываешь** → INDEX (где что) → README (раздел по теме) → код. Не читать файлы «на всякий случай».
3. **Меняешь** → точечно, в рамках задачи. Архитектурные решения — сначала слово человеку.
4. **Проверяешь** → минимум сборка/тесты; для UI/рантайм — живой запуск, если это возможно без риска.
5. **Финализируешь** → см. «Поддержание порядка».

## Как принято (правила проекта)
- **Секреты, токены, пользовательские креды** — никогда в вывод, логи, коммиты, память.
- **Прод и инфраструктура, через которую ты сам работаешь** — только атомарные, заранее подготовленные изменения: собрал → проверил → один стейдж → check → apply. Не «стоп-потом-старт» частями.
- **Окно консоли, где запущен сервис пользователя** — сакрально: обновление = «остановить в ней же и в ней же запустить», не убивать и не открывать новое.
- **Git**: завершённая веха = коммит и пуш (не копить незакоммиченное). `git add -A` вслепую нельзя — секреты/бинарники/venv проверяются по `git status --porcelain` до стейджинга.
- **Язык интерфейса/комментариев**: [RU/EN — как в проекте].
- **Не трогай** чужие процессы/порты/каталоги без проверки, чьи они; на этой машине параллельно работают другие агенты над другими продуктами.

## Поддержание порядка (ОБЯЗАТЕЛЬНОЕ)
Документация — не витрина, а рабочий инструмент. Каждый агент, закончивший нетривиальную работу, обязан:
1. **STATE-LOG**: в конец [docs/STATE-LOG.md](docs/STATE-LOG.md) — запись финала сессии (формат внутри файла: волна, что сделано с фактами и хабами, что открыто/отложено, HEAD).
2. **AGENTS.md**: новые правила/предпочтения человека — сюда (кратко!). **INDEX.md**: создал/удалил/переименовал файл — добавь/убери строку каталога. **MAP.md**: появились горячая/запретная зона — обнови.
3. **README**: если менялась архитектура/фичи/ловушки — обнови соответствующий раздел. Не должен отставать от кода.
4. **Проверяй пути**: каждая ссылка в документах должна вести в реальное место (`Test-Path`/`ls` перед выдачей). Документ с выдуманными путями хуже отсутствия.
5. **Одно дерево**: дерево проекта живёт в ОДНОМ месте — README «Структура». В MAP — только семантика (горячее/чужое/без доверия).
6. **Финал смены** (человек уходит / «сессия завершена»): доки обновлены, всё закоммичено, `0/0` с origin, рабочее дерево чистое.

## Неразбериха в документах?
Индекс не врал: если файл противоречит другому — **код истиннее**. Найди расхождение, почини документы в этом же прогоне, запиши в STATE-LOG.
