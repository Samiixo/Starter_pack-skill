## Порядок работы
1. **Заходишь** -> хвост [docs/STATE-LOG.md](docs/STATE-LOG.md) (читать с конца),
   плюс `git status` и `git log -3`.
2. **Разведываешь** -> [INDEX.md](INDEX.md) (где что) -> нужный раздел README ->
   код. Не читать файлы "на всякий случай".
3. **Меняешь** -> точечно, в рамках задачи. Архитектурные решения - сначала
   человеку.
4. **Проверяешь** -> минимум сборка и тесты; для UI и рантайма - живой запуск,
   если это возможно без риска.
5. **Финализируешь** -> таблица в разделе "Поддержание порядка" говорит, какой
   файл обновить в какой ситуации.

## Как принято (правила проекта)
- **Секреты, токены, пользовательские креды** - никогда в вывод, логи, коммиты,
  память.
- **Прод и инфраструктура, через которую ты сам работаешь** - только атомарные,
  заранее подготовленные изменения: собрал, проверил, один стейдж, применил. Не
  "остановил - потом запустил" частями.
- **Окно консоли, где запущен сервис человека**, - сакрально: обновление значит
  "остановить в нём же и в нём же запустить", не убивать и не открывать новое.
- **Git**: завершённая веха - коммит и пуш, не копить незакоммиченное.
  `git add -A` вслепую нельзя: секреты, бинарники и `venv` проверяются по
  `git status --porcelain` до стейджинга.
- **Язык интерфейса и комментариев**: [RU или EN - как в проекте].
- **Не трогай** чужие процессы, порты и каталоги без проверки, чьи они: на
  машине параллельно могут работать другие агенты над другими продуктами.
- **[Сезонные заморозки]**: [например, "UI-фичи X не делать без прямой просьбы -
  человек сам скажет, когда откроется"].

## Поддержание порядка (обязательное)
Документация - не витрина, а рабочий инструмент. Каждый агент, закончивший
нетривиальную работу, обновляет ровно те файлы, которых коснулась работа:

| Ситуация | Файл | Что сделать |
|---|---|---|
| Нетривиальная работа | [STATE-LOG](docs/STATE-LOG.md) | запись в конец |
| Новое правило человека | [AGENTS.md](AGENTS.md) | строка в "Как принято" |
| Файл создан, удалён, переименован | [INDEX.md](INDEX.md) | строка каталога |
| Появилась горячая или чужая зона | [MAP.md](MAP.md) | строка в таблицу |
| Изменилась архитектура или фичи | README.md | обновить раздел |
| План отвергнут или отложен | [AGENTS.md](AGENTS.md) | строка в "Заморожено" |

Правило путей: каждая ссылка в документе ведёт в реальное место, а документ с
выдуманными путями хуже отсутствия. Теперь правило проверяемо: линтер комплекта
сверяет ссылки, плейсхолдеры и символы - `python tools/doc_lint.py .` (скрипт
идёт вместе с комплектом, а не лежит в самом проекте).

Одно дерево: дерево проекта живёт в одном месте - README, раздел "Структура". В
MAP только семантика: где больно, где чужое, где доверия нет.

Финал смены (человек уходит или говорит "сессия завершена"): доки обновлены, всё
закоммичено, `0/0` с `origin`, рабочее дерево чистое.

## Что НЕ надо делать
- Не дублировать дерево проекта: оно живёт в README, раздел "Структура".
- Не писать мёртвые ссылки: путь проверяется до того, как попасть в документ.
- Не переписывать историю журнала: [docs/STATE-LOG.md](docs/STATE-LOG.md) только
  дописывается, старые записи не редактируются.
- Не возвращать замороженные планы: их снимает только прямой запрос человека.

документы в этом же прогоне, запиши в [docs/STATE-LOG.md](docs/STATE-LOG.md).

## Первичная настройка (один раз, после заполнения раздел УДАЛИТЬ)
1. Замени все `[...]`-плейсхолдеры фактами из репо. Не выдумывай: проверь
   структуру, `git remote -v`, README, файлы сборки.
   Проверка: незаполненных `[...]` в файле не осталось.
2. Заполни [MAP.md](MAP.md): 3-6 горячих зон (где правки болят), внешние миры,
   "не открывать", "слои без доверия".
   Проверка: в MAP.md нет пустых таблиц-заглушек, каждая строка называет зону.
3. Заполни [INDEX.md](INDEX.md) реальными файлами по слотам; пустые слоты удали.
   Проверка: линтер не находит ссылок в никуда.
4. Создай `docs/STATE-LOG.md` по шаблону и запиши первую запись "настроен
   док-порядок, HEAD=X".
   Проверка: журнал оканчивается записью с датой и HEAD.
5. Если нет каталога `docs/` - создай. Если нет git - предложи человеку
   инициализацию, сам не решай.
   Проверка: `docs/` есть; git отвечает или явно записано "git нет".
6. Удали этот раздел "Первичная настройка" из файла.
   Проверка: поиск по "Первичная настройка" в AGENTS.md больше ничего не находит.

Границы сканирования при разведке: исключи `node_modules/`, `.git/`, сборочные
`dist/`, `venv/`, данные с секретами, временные `tmp/`.
